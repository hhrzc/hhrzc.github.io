Papaya Injection

$ gradlew build --module ppi

A hub for your selectors — declarative, interface-based locators for Playwright and Selenium. Describe every selector as a method on an interface (inline or externalized to a properties-style file), and the library builds a dynamic proxy that resolves it to a real Locator (Playwright) or WebElement (Selenium) — lazily, exactly when and where you call it.

Checkpoints

💤
Lazy by design
Nothing is resolved until you actually call the method — declare your selectors once, use them wherever and whenever your test flow needs them.
🔌
Driver supplied per call
The driver/page is passed in when an element is resolved, not upfront — the same declared element can resolve against different drivers or pages without a page object per driver.
🧩
Interfaces over classes
A deliberate, declarative style in the spirit of JPA/Spring Data — no excessive extending or instantiating, especially convenient alongside Spring dependencies.
🗂️
Two ways to define selectors
Inline on the method via annotations, or externalized into a mapped .telemetry properties file and referenced by key — your choice, per project or per interface.

Installation

Playwright + Spring, via Gradle or Maven

implementation("io.github.hhrzc:ppi-playwright-spring:0.1.0")
<dependency>
    <groupId>io.github.hhrzc</groupId>
    <artifactId>ppi-playwright-spring</artifactId>
    <version>0.1.0</version>
</dependency>

Playwright/Selenium and Spring are compileOnly — add your own versions of com.microsoft.playwright:playwright, org.seleniumhq.selenium:selenium-java, and/or org.springframework:spring-context alongside this library.

Usage

Define once as an interface, resolve lazily wherever you need it

Inline selector via annotation

@Telemetry
public interface LoginPage extends PpiRepository {

    @Sensor("$//button[name='SignIn']")
    LocatorSupplier signInButton();

}

Externalized into a .telemetry file, referenced by key

@Telemetry("main_pages/login_page.telemetry")
public interface LoginPage {

    @Sensor("button.sign-in")
    LocatorSupplier signInButton();

}

// login_page.telemetry
button.sign-in=//button[name='SignIn']

Parameterized selectors with @Param

@Sensor("$//button[@name='{name}']")
LocatorSupplier buttonByName(@Param("name") String name);

// usage
Locator signInButton = loginPage.buttonByName("SignIn").apply(page);

Resolving against the driver/page

LoginPage loginPage = WebElementIgniter.ignite(LoginPage.class);
Locator signInButton = loginPage.signInButton().apply(page);
// or, for Selenium: WebElement el = loginPage.signInButton().apply(driver);

A default XPath search is used unless you pass BY.CSS as the first parameter, and a PostfixLocator can be supplied to chain something like .nth(1) onto the resolved locator.
